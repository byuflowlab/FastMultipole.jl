## Context

Item `022` (GPU device-resident FMM lifecycle,
`MATRIX_OPERATOR_REFACTOR/022-impl-gpu-device-resident-m2l.md`) is unapproved after
four rejections. The single recurring blocker: the middle passes must keep **all**
expansion buffers device-resident across B2M→M2M→M2L→L2L→L2B with zero mid-pipeline
host copies (`expansion_host_copies == 0`), and implement the operators as
array-generic code that runs identically on `Array` (this CUDA-less Mac) and
`CuArray` (remote GPU).

Progress so far:
- **B2M** and **M2M** are genuinely resident. `022b` (already landed in
  `src/translate_batched.jl`) built the array-generic M2M path:
  `resident_m2m_batch!` (`SharedRotationM2M`/`DenseTranslationM2M`) over the GEMM-native
  `DegreeMajorRealBuffer`, driven by `_launch_resident_m2m!` (level-sequential,
  no scalar indexing, no host copies), with `_launch_host_m2m!` /
  `_launch_cuda_resident_m2m!` delegating to it.
- **M2L** (`_launch_host_m2l!` at `src/translate_batched_resident.jl:202`) and
  **L2L** (`_launch_host_l2l!` at `:242`) still gather/scatter expansion **columns
  scalar-by-scalar** and call the flat item-016 operators. Fine on `Array`, but on
  `CuArray` this requires `@allowscalar` and forces host round-trips — the CUDA
  variants `_launch_cuda_resident_m2l!`/`_launch_cuda_resident_l2l!`
  (`src/translate_batched_cuda.jl:1243/1280`) copy each column device→host, run the
  CPU operator, scatter back, and (post-2026-07-01) correctly bump
  `expansion_host_copies`, so the resident invariant is *provably violated*.

**022c closes the M2L and L2L gap** by extending the exact `022b` pattern: an
array-generic `resident_m2l_batch!` / `resident_l2l_batch!` over
`DegreeMajorRealBuffer`, driven by `_launch_resident_m2l!` / `_launch_resident_l2l!`
with no scalar indexing and no host copies, validated on the CPU `Array` path against
the item-016 operator oracle. After 022c only **L2B** remains as a resident-blocking
pass (deferred to 022d — it needs a device `evaluate_local`, which has no
degree-major GEMM analog yet). M2L is the `008c`/`015` core deliverable: its batches
are per-offset-class (one `(level, offset)` ⇒ one `(r,θ,φ)` shared across the whole

Scope is **M2L + L2L only** (per user decision). B2M/M2M untouched.

## Phase 1 — Build the M2L/L2L operator machinery (missing analogs of the M2M helpers)

In `src/translate_batched.jl`:
1. `_m2l_z_block_matrix` + `_m2l_ztranslate_shared!(out, in, blocks, maps, …)` —
   analog of `_m2m_z_block_matrix`/`_m2m_ztranslate_shared!` (`:1433`/`:1445`) using
   `m2l_z_blocks!`/`m2l_z_block_index`. NOTE the M2L z-block is the multipole→local
   coupling and is **dense per-`m`** (not triangular like M2M/L2L). Use the same
   `P_loop`/`P_block` two-parameter convention as `_m2m_ztranslate_shared!`: the
   order-aware `apply_m2l_z!` (`:314`) sizes blocks by `P_active` but sums the φ
   channel only over `n, np ≤ P_phi`, so `_m2l_z_block_matrix(TF, blocks, m, P_loop,
   P_block)` extracts the `m:P_loop` sub-block from `P_active`-indexed storage; call
   with `(P_phi, P_active)` for φ and `(P_active, P_active)` for χ. No small-P
   fallback.
2. `_l2l_z_block_matrix` + `_l2l_ztranslate_shared!` — same, using
   `l2l_z_blocks!`/`l2l_z_block_index` (upper-triangular per `m`).
3. `_lh_local_shared_gen!(out_phi, out_chi, in_phi, in_chi, lh_A, lh_B, maps_phi,
   maps_chi, P_phi, P_active)` — analog of `_lh_multipole_shared_gen!` (`:1528`) using
   `lamb_helmholtz_local_coeffs!`. Used by both M2L return and L2L (local channel).
   **Gap to close first:** the local χ coupling is the *upper* neighbor
   `χ_n += b·χ_{n+1}`, but `DegreeMajorMaps` (`:1267`) only has `row_down`
   (multipole `χ_{n-1}→χ_n` direction). Add a `row_up` field:
   `n < P ? degree_row_offset(n+1) + k : row` — dof `k` maps to the same `(ri,m)` in
   degree `n+1` because the within-degree dof order is a prefix. The local
   `_lh_row_coefficients` analog must zero the `b` row at the top degree
   (`n = P_active` has no upper neighbor), mirroring how the multipole version zeroes
   `b` where `n == m`.
4. `resident_m2l_batch!(strategy, targets::DegreeMajorRealBuffer, sources, phis, thetas,
   rs, cache, Val(LH))` and `resident_l2l_batch!(…)` — mirror `resident_m2m_batch!`,
   swapping in helpers 1–3 and the **local** y-modes. **Strategy-tag seam:** the leading
   argument is an `AbstractResidentM2LStrategy` tag, mirroring the M2M pair
   (`src/containers.jl:1037-1039`). Add in `src/containers.jl` (placement rule 1):
   `abstract type AbstractResidentM2LStrategy end`,
   `struct SharedRotationM2L <: AbstractResidentM2LStrategy end` (the factored path
   022c implements: batch-shared `U_n`/`V_n` swap GEMMs, per-batch `e^{iνθ}`/`Z_φ`
   diagonals and `K_m(r)` z-blocks — all batch-constant for M2L since each offset
   class shares one `(r,θ,φ)`), and
   `struct DenseTranslationM2L <: AbstractResidentM2LStrategy end` (materialized
   per-offset-class dense `D×D` operator, one GEMM per batch, analog of
   `DenseTranslationM2M`/`build_dense_m2m_operator`). 022c implements **only**
   `SharedRotationM2L`; the `DenseTranslationM2L` method is a stub that throws
   `ArgumentError("DenseTranslationM2L is deferred to 019/024")` so the seam is
   concrete without expanding scope. L2L gets no strategy tag in 022c (single shared
   path; its per-level batches mix θ/φ across the 8 child octants, so the dense
   per-class case is weaker there — revisit in 019 if profiling warrants). Name intermediates by stage as
   in `resident_m2m_batch!` (`aphi/yphi/zphi`), not the flat pipelines' `mid/tmp`
   ping-pong. Accept the batch-shared invariants (`DegreeMajorMaps`, U/V mode blocks)
   as arguments built once per launch (see helpers 5–6), rather than rebuilding per
   call. Assert uniform `(r,θ,φ)` for M2L / uniform `r` for L2L (guaranteed per
   batch/level by the launcher). Correctness contract: bit-for-bit parity (to fp
   tolerance) with the corresponding flat item-016 operator batch. **Verified
   (2026-07-01 review):** the multipole-vs-local factored y-stage distinction is
   carried entirely by the `U`/`V` mode matrices (`rotate_batched.jl:774-798`,
   `:977-988`) — same staged arithmetic, same `+θ`, no extra-π adjustment — so
   `_factored_y_degree_major_gen!` is reused unchanged with `y_loc_U`/`y_loc_V`.
5. `_launch_resident_m2l!(state, strategy=state.options.m2l_strategy)` — mirror
   `_launch_resident_m2m!`'s strategy plumbing; build the per-launch invariants once
   (`DegreeMajorMaps`, `_ymode_real_blocks` for both mode pairs,
   `_degree_major_to_flat_indices`); then iterate `state.interaction_list.m2l_batches`.
   Each batch is one offset class ⇒ constant `(r,θ,φ)`, computed **on host from
   `batch.offset` and the level cell width** (`offset .* (2h0/2^level)`) — no device
   `node_centers` reads. Routes are batch-contiguous by construction
   (`_flatten_radix_routes_host`), so index each batch as a `route_lo:route_hi`
   **range view of the device `route_sources`/`route_targets`** (valid fancy-index
   operands) — do not `Array(...)`-download the route arrays (they are
   per-interaction, large). Degree-major gather sources from `state.multipoles`;
   `resident_m2l_batch!` into a degree-major target; accumulate into `state.locals`
   with a **plain fancy-indexed add** (`A[:, idx] = A[:, idx] .+ B`): within one
   offset-class batch each target appears at most once (target + fixed offset ⇒
   unique source; batches built per `(level, offset)` in
   `interaction_list_batched.jl:235-239`), and accumulation across batches is
   sequential — no scatter-matrix GEMM needed. Add a one-time host-side setup
   assertion of within-batch target uniqueness on `interaction_list` metadata. Zero
   `state.locals` once up front.
6. `_launch_resident_l2l!(state)` — level-sequential top-down `1…ell` (parents already
   filled); collect edges by parent-level from `l2l_parent_routes`/`l2l_child_routes` +
   `grid.node_levels`. **Translation-vector direction: `child − parent`** (as in
   `_launch_host_l2l!` `:257`) — the opposite of M2M's `parent − child`
   (`_launch_resident_m2m!` `:1681`); state it in the docstring. Extract the shared
   push!-based edge/angle collection loop (repeated in `_launch_resident_m2m!`
   `:1676-1690`, `_launch_host_l2l!` `:246-266`, `_launch_cuda_resident_l2l!`) into one
   `_collect_level_edges(routes_parent, routes_child, node_levels, node_centers,
   level, direction)` helper used by resident M2M and L2L. Group by `r` (uniform per
   level, same argument as M2M); gather parent columns from `state.locals`,
   `resident_l2l_batch!`, scatter-add into child `state.locals` columns. Children are
   unique per edge → scatter is a plain gather-add (no scatter matrix).
