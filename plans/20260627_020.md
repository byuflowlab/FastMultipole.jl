# Implement Item 020: Storage-Minimal Radix Grid Clustering

## Summary
Add the radix-path uniform-grid clustering layer with minimal persistent storage. `RadixGrid` will store only
root geometry, the sorted body permutation, sorted occupied Morton keys, and compact body range metadata. Cell
coordinates, centers, widths, radii, offsets, and distances are derived through accessors.

## Key Changes
- Add `RadixGrid{TF}` in `src/containers.jl` with persistent fields:
  - `x_min::SVector{3,TF}`
  - `h0::TF`
  - `ell::Int`
  - `perm::Vector{Int}`
  - `cell_keys::Vector{UInt64}`
  - `cell_ranges::Matrix{Int}` as `2 x M`, row 1 = first sorted body index, row 2 = body count
- Add `src/tree_batched.jl`, include it from `src/FastMultipole.jl`, and export `RadixGrid`.
- Implement construction with deterministic root domain, `ell <= 21`, quantization, temporary body keys,
stable sort by `(key, original_index)`, and occupied-cell compression.
- Do not physically move user bodies.
- Derive grid resolution, cell width/half-width/radius, Morton decode, cell coord/center, body ranges,
offsets, and displacements through accessors.
- Use binary search over sorted `cell_keys` for lookup; do not store a dict.
- Defer `invperm`, sorted physical buffers, interaction lists, GPU upload, and operator execution.
