### Fixes applied after job 12859365 (2026-07-21)

1. **Device allocation on dense M2L (`dev_alloc == 0` failed, all 12 configs).**
   ROOT CAUSE (confirmed by job 12864821 showing byte-identical alloc after the
   first attempt): the packed 3-D operator `operators[:,:,k]` slice / reshape
   reaches `mul!`'s generic (allocating pool-workspace) fallback, not classic
   cuBLAS gemm. FINAL FIX: store operators as `Vector{CuMatrix{TF}}` (one D×D
   device matrix per class — a plain `DenseCuMatrix`, matching the host plan's
   `Vector{Matrix}` and the concat path's `phi_dense::CuMatrix`); the per-class
   `mul!(@view dst[:,lo:hi], operators[k], @view src[:,lo:hi])` with contiguous
   column-range slab operands then dispatches to classic zero-workspace gemm.
   `src/translate_batched_cuda.jl` (build loop + `_cuda_dense_class_gemm!`), and
   `test/cuda_radix_integration_test.jl` (operator now a Vector: `dops[k]`,
   per-class `dense_numeric`, `operators isa AbstractVector` typing).
   The first attempt (reshape-of-flat-view + single-level base-slab views) was
   NECESSARY but INSUFFICIENT and is superseded by the Vector layout.
2. **Float32 dense operators overflow to Inf/NaN at high P** (closest displacement
   classes; the combined rotation·z-translation·rotation matrix has larger dynamic
   range than any single factored stage — inherent to dense materialization, NOT a
   port bug; device operators are bit-exact copies of the host oracle). Test now
   uses NaN-safe `isequal` for operator-upload fidelity and gates numerical parity
   / accuracy on `dense_numeric = all(isfinite, dops)`; the alloc check stays
   unconditional. `test/cuda_radix_integration_test.jl`.
3. **Stale one-shot error assertion** in `test/cuda_radix_lifecycle_test.jl:594`
   updated from `"host-only"` to `"one-shot"` (the message changed when dense
   became recurring-cache-supported).
