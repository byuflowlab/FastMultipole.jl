# Plan 022b: M2M diagonal kernelization + resident-state wiring

## Context

Task `022` (GPU device-resident FMM) needs a genuinely device-resident M2M. A prior
session (plan `functional-forging-biscuit`, now superseded by this file) already landed
and validated the **operator core** on CPU:

- New GEMM-native buffer `DegreeMajorRealBuffer` + `AbstractCoefficientBuffer` supertype
  + `to_gemm_buffer!`/`to_flat_buffer!` converters (`src/containers.jl`).
- Two swappable strategies `SharedRotationM2M` / `DenseTranslationM2M` under
  `AbstractResidentM2MStrategy`, entry `resident_m2m_batch!(strategy, targets, sources,
  phis, thetas, rs, cache, Val(LH))` (`src/translate_batched.jl`), accumulating into
  `targets`.
- Parity vs the task-016 `m2m_operator_batch!` oracle for `Val(false)`/`Val(true)` ×
  `Float64`/`Float32` × P=0,1,2,5 in `test/resident_m2m_gemm_test.jl` (wired into
  `test/runtests.jl`). 016 suite unregressed (23260/23260).

**Two gaps remain, which THIS plan closes:**

1. **GPU-generic diagonals.** The `mul!` GEMMs are array-generic, but four helpers in
   `src/translate_batched.jl` still use scalar indexing (fine on `Array`, but scalar
   indexing on `CuArray` requires `@allowscalar` and is slow): `_zphi_degree_major!`,
   the `e^{iνθ}` middle loop inside `_factored_y_degree_major!`,
   `_m2m_ztranslate_degree_major!`, `_lh_multipole_degree_major!`.
2. **Resident-state wiring.** The resident M2M passes are still the CPU-in-disguise
   `@allowscalar` host round-trip: `_launch_host_m2m!` (`src/translate_batched_resident.jl:198`)
   and `_launch_cuda_resident_m2m!` (`src/translate_batched_cuda.jl:1239`, which uses
   `_copy_cuda_column_to_host!`/`_scatter_host_column_to_cuda!` and trips
   `_assert_cuda_resident_stage!`'s `expansion_host_copies == 0`).

**Outcome:** one array-generic `_launch_resident_m2m!(state, strategy)` that runs the
GEMM strategies with **no scalar indexing and no host copies**, so the same code runs
on `Array` (this Mac, no CUDA) and `CuArray` (GPU). Scope is **M2M only**; per user
decision the resident state keeps `FlatCoefficientBuffer` and the launcher converts
flat↔degree-major *during gather/scatter* (once per pass, not per GEMM). B2M / M2L /
L2L / L2B are untouched — no regression to the passing host resident lifecycle.

## Key facts a cold agent needs (all verified this session)

- **Degree-major layout** (`DegreeMajorRealBuffer`): real, `(P+1)²` rows per channel,
  degree-major; degree `n` occupies `degree_row_range(n) = (n²+1):((n+1)²)` (`2n+1`
  rows) in y-mode dof order (`_ymode_dof_to_storage`: k=1→(re,m0); k=2m→(re,m);
  k=2m+1→(im,m)). `im(m0)` is structurally 0 and dropped.
- **r is constant across all M2M edges at a level.** In the radix octree the child
  center = parent center ± quarter-width per axis, so `|parent_center − child_center|`
  is identical for every edge at that level; only θ,φ vary (8 octant directions). ⇒
  the z-translation blocks and LH coefficients are **shared per level** (build once,
  GEMM across the whole level batch). Exploit this in the launcher.
- **M2M return alignment uses the SAME `y_mult_U/V` modes at `+θ`** as the source
  (confirmed empirically). Already implemented in `resident_m2m_batch!`.
- Reusable primitives: `m2m_z_blocks!`/`m2m_z_block_index`/`m2m_z_block_length`
  (`src/translate_batched.jl`), `lamb_helmholtz_multipole_coeffs!`,
  `z_theta_batch_diagonals!` (`src/rotate_batched.jl:593`), the cache
  `y_mult_U`/`y_mult_V` and `_ymode_real_blocks` extractor. `harmonic_index`,
  `flat_basis_index`, `degree_row_offset`, `degree_row_range`.
- Resident state: `DeviceResidentRadixState{TF,B,LH}` (`src/containers.jl:1141`);
  `multipoles`/`locals::FlatCoefficientBuffer{TF,<:AbstractMatrix{TF},B,LH}`,
  `invariant_cache::Any`, `scratch::Any`, `options::CUDARadixLifecycleOptions{TF}`.
  M2M routes: `m2m_parent_routes`/`m2m_child_routes`; `grid.node_levels`,
  `grid.node_centers`. Existing `_launch_host_m2m!` shows the level/edge collection
  pattern to reuse.

## Workstream 1 — GPU-generic reformulation (no scalar indexing, no new deps)

Reformulate the four helpers as broadcasts + index-gathers over precomputed arrays. All
of `mul!`, broadcast (`.=`, `.*`), and integer-index gather/scatter are array-generic
(CUDA.jl supports them); **no KernelAbstractions / NNlib needed**. Precompute per-order
(P-only) index/sign vectors once, moved to the state's array type; coefficient *values*
are per-level (uniform r).

Precomputed P-only vectors (build in a small struct, e.g. `DegreeMajorMaps`):
- `row_m::Vector{Int}` (len `(P+1)²`): m-value of each degree-major row.
- `row_ssign::Vector{TF}`: −1 on re-rows, +1 on im-rows (0/any on m0 — unused since sin=0).
- `row_pair::Vector{Int}`: permutation swapping each (re↔im) row; m0 rows map to self.
- `row_down::Vector{Int}` (χ): maps each (n,m) row to the (n−1,m) row; sentinel where n=m.
- per-degree `nu_n = -n:n` for the middle diagonal.

Generic helpers (add `_gen!` variants; keep the scalar ones for the standalone operator
tests / arbitrary-r):
- `_zphi_degree_major_gen!(slab, phis, maps, inverse)`:
  `A = row_m .* transpose(phis); C = cos.(A); S = sin.(A); sw = slab[row_pair, :];`
  `slab .= C.*slab .+ ((inverse ? -1 : 1) .* row_ssign .* S) .* sw`. (m0 rows: S=0 ⇒
  identity, correct.)
- `_factored_y_degree_major!` middle stage: per degree, replace the scalar `e^{iνθ}`
  loop with `Cd = cos.(nu_n .* transpose(thetas)); Sd = sin.(...); Gre2 = Cd.*Gre .-
  Sd.*Gim; Gim2 = Sd.*Gre .+ Cd.*Gim`. The V/U `mul!`s already generic.
- z-translate, uniform r (per level): build `blocks = m2m_z_blocks!(·, r_level, P_active)`
  once; for each m, gather the strided (m,re)/(m,im) rows across degrees into
  `(P−m+1)×N` matrices, `mul!` by the lower-triangular block `Bm` (built from `blocks`
  via `m2m_z_block_index`), scatter back. Precompute per-m row-index vectors. Add
  `_m2m_ztranslate_shared!(out, in, blocks, maps, P_loop, P_block)`.
- LH coupling, uniform r (per level): build `lh_A`/`lh_B` once via
  `lamb_helmholtz_multipole_coeffs!`; φ update = `out_phi = in_phi .+ arow .*
  chi[row_pair,:]` with a per-row signed `arow`; χ update = `out_chi = in_chi .+ brow
  .* chi[row_down,:]` (brow=0 where n=m). Add `_lh_multipole_shared_gen!`.

`resident_m2m_batch!(SharedRotationM2M(), …)` switches to these `_gen!`/shared helpers.
It may assume uniform `rs` (asserted; the launcher guarantees it per level). Keep
`DenseTranslationM2M` as-is (already `mul!`-generic; per-vector K build is host-side).

## Workstream 2 — resident wiring (M2M-local conversion)

Add one array-generic launcher used by both host and CUDA paths:

`_launch_resident_m2m!(state, strategy)` — level-sequential `ell−1 … 0`:
1. Collect edges with parent at this level from `m2m_parent_routes`/`m2m_child_routes`
   + `grid.node_levels` (reuse `_launch_host_m2m!`'s collection). Compute the shared
   `r_level` and per-edge θ,φ from `grid.node_centers` (`cartesian_to_spherical`).
2. **Gather + convert flat→degree-major:** precompute `dm_to_flat_phi`/`dm_to_flat_chi`
   (degree-major row → flat row, via `_ymode_dof_to_storage`+`flat_basis_index`).
   `src_dm.phi .= @view state.multipoles.phi[dm_to_flat_phi, child_nodes]` (double
   index-gather, generic; χ likewise).
3. `tgt_dm` zeroed; `resident_m2m_batch!(strategy, tgt_dm, src_dm, phis, thetas,
   fill(r_level,N), cache, Val(LH))`.
4. **Scatter-add + convert degree-major→flat into parents.** Parents repeat within a
   level (many children→one parent) ⇒ duplicate-safe accumulation. Preferred generic
   form: an edge→parent scatter matrix `Sscat` (n_edges × n_parents, 0/1) and
   `state.multipoles.phi[dm_to_flat_phi, parents_unique] .+= (tgt_dm.phi) * Sscat`
   (one GEMM, generic, duplicate-safe); or a host loop over edges doing full-column
   vector adds (generic, no scalar indexing). χ likewise.
No `@allowscalar`, no `_copy_cuda_column_to_host!`/`_scatter_host_column_to_cuda!` ⇒
`expansion_host_copies` stays 0.

Wire-in:
- `src/translate_batched_resident.jl`: replace `_launch_host_m2m!` body with a call to
  `_launch_resident_m2m!(state, strategy)` (Array-backed state).
- `src/translate_batched_cuda.jl`: replace `_launch_cuda_resident_m2m!` body likewise;
  delete the M2M `@allowscalar` block and its host-copy helpers usage. The CuArray
  path uses the identical `_launch_resident_m2m!`.
- Strategy selection: add `m2m_strategy::AbstractResidentM2MStrategy` to
  `CUDARadixLifecycleOptions` (`src/containers.jl`), default `SharedRotationM2M()`;
  the launchers read `state.options.m2m_strategy`. (Keep the M2L `operator` field.)
- `state.invariant_cache` provides `basis_info`/`OperatorInvariantCache`; reuse it for
  the y-modes rather than rebuilding per call.

## Risks / notes
- **Uniform-r assumption**: the shared z-block/LH path requires equal `rs` per call; the
  launcher supplies one level at a time. Assert it; keep the per-column scalar helpers
  for the arbitrary-r standalone operator API/tests.
- **Scatter duplicates**: parents repeat within a level — must accumulate (scatter
  matrix GEMM or column-add loop), never `A[:,dupidx] .+= B`.
- **im(m0)=0 invariant** holds through M2M (LH transient dropped safely) — do not
  reintroduce im(m0) storage.
- Broadcasts allocate temporaries; acceptable for correctness-first. A later pass can
  preallocate scratch (state array type) if profiling warrants.
- This increment does not make the full CUDA lifecycle pass end-to-end (M2L/L2L/L2B
  remain follow-ups); it makes M2M genuinely resident and array-generic and removes the
  M2M host-copy contradiction.
