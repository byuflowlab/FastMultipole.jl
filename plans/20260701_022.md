## 1. Confirmed root cause (already investigated — do not re-investigate)

Item 022 requires: upload bodies once, keep **all** expansion buffers on device across
B2M → M2M → M2L → L2L → L2B, download only per-body influence at the end, and implement M2L as
batched GEMM over translation-invariant offset classes (per `008c`/`015`).

What the code actually does (as of 2026-07-01):

1. `_launch_cuda_resident_m2m!` / `_m2l!` / `_l2l!` in `src/translate_batched_cuda.jl`
   (~lines 1244–1358) wrap their bodies in `CUDA.@allowscalar` and:
   - copy expansion columns device→host **one scalar at a time** via
     `_copy_cuda_column_to_host!` (~line 1149),
   - allocate **fresh host** `FlatCoefficientBuffer`s and run the **CPU** operator batches
     (`m2m_operator_batch!` etc.) on them,
   - scatter results back to device via `_scatter_host_column_to_cuda!` (~line 1162).
   This is the host-mirror path (nominally removed 2026-06-30) smuggled back through scalar
   indexing. **Not device-resident.** The batched-GEMM M2L deliverable is entirely absent.
2. `state.counters.expansion_host_copies` is **never incremented** despite these copies, so
   `_assert_cuda_resident_stage!` (~line 1101) asserting `expansion_host_copies == 0` gives
   **false confidence**.
3. Device `state.scratch.*` buffers are allocated and asserted resident
   (`test/cuda_radix_lifecycle_test.jl` ~lines 500–503) but the operator loops never use them
   — a fourth false-confidence gap.
4. `_copy_radix_output_to_host_target_buffer!(..., grid::DeviceRadixGrid, ...)`
   (`src/translate_batched_cuda.jl:998`) downloads `grid.perm`/`body_system`/`body_index` via
   `Array(...)` at host finalization — extra transfers beyond the single influence download.

The user's original 3-point feedback (blocking scalar access; tests validate math not
residency; medium metadata download) is **correct**. This plan adds: the missing batched-GEMM
M2L is the core deliverable not a detail; the unused scratch assertions are a fourth gap; and
the self-enforcing fix is running under `CUDA.allowscalar(false)` with the `@allowscalar`
blocks deleted so non-residency errors instead of passing.

## 2. Phase A — CPU-validatable honesty + oracle hardening (runs on THIS host)

Do this first. Eliminates false confidence and locks in the oracle before any GPU code.

**A1. Count host copies honestly.** In `src/translate_batched_cuda.jl`, make
`_copy_cuda_column_to_host!` and `_scatter_host_column_to_cuda!` increment
`state.counters.expansion_host_copies` (thread `counters`/`state` through, or increment at
each call site). After this, any path that round-trips through host shows a non-zero counter —
converting "silently non-resident" into "provably non-resident." (Phase B deletes these
helpers entirely; A1 is the interim honesty guard and protects against regression.)

**A2. Remove misleading scratch-residency assertions.** In `_assert_cuda_resident_stage!` /
`_assert_cuda_scratch_resident!`, drop coverage of the `state.scratch.*` device fields that
the operator loops do not honor. Keep expansion-buffer (`multipoles`, `locals`, `output`) and
route/metadata residency assertions. (Phase B re-adds scratch assertions once the real kernels
actually use those buffers.)

**A3. Fix host-target metadata download (feedback point 3).** For the
`grid::DeviceRadixGrid` overload of `_copy_radix_output_to_host_target_buffer!`
(`src/translate_batched_cuda.jl:998`), stop calling `Array(grid.perm)` /
`Array(grid.body_system)` / `Array(grid.body_index)` at finalization. Either:
- route through the existing device scatter `_copy_radix_output_to_device_target_buffer!` +
  `_cuda_scatter_output_to_target_buffer_kernel!` (~lines 1021–1057) into a device buffer, then
  do a **single** contiguous download; or
- allocate a host mirror of `perm`/`body_system`/`body_index` **once** at `cuda_radix_state`
  setup and count it in the transfer counters there — not at finalization.
No per-body-metadata `Array(...)` at pipeline end.

**A4. Harden the CPU oracle tests.** In `test/cuda_radix_lifecycle_test.jl`, strengthen the
CPU-safe (host-mirror) branch to assert full end-to-end `state.output` parity of
`run_host_radix_lifecycle!` against a trusted independent reference (legacy CPU operator path
or a direct all-pairs sum — see `direct!` and `test/gravitational.jl`), for `Val(false)`,
`Val(true)`, `Float64`, and a `Float32` tolerance smoke. This makes the oracle trustworthy
independent of any GPU code.

**Phase A verification (all must be green on this host):**
```sh

julia --project=. test/radix_interaction_list_test.jl
julia --project=test -e 'push!(LOAD_PATH, pwd()); include("test/runtests.jl")'
```
Note: the existing threaded extra-farfield case is reported `Broken`, not failed — that is
pre-existing and expected.

## 3. Phase B — Genuine device-resident GPU kernels (written here, validated remotely)

Replace the `@allowscalar` host round-trips with real device execution. **Delete**
`_copy_cuda_column_to_host!`, `_scatter_host_column_to_cuda!`, and every `CUDA.@allowscalar`
block from the operator stages. Recommended kernel strategy: **batched GEMM**, because
`MaterializedYRotationM2L` is rotate·translate·rotate = dense matmuls, matching the
`008c`/`015` design.

**B1. M2L via per-offset-class strided-batched GEMM (core deliverable).** Each
`list.m2l_batches` entry shares one integer offset ⇒ one `(r,θ,φ)` ⇒ **one** operator matrix
`Op` for the entire batch (translation invariance is exactly why the stencil batches by
offset). Steps:
- Build the small dense `Op` per offset class. Reuse the CPU `MaterializedYRotationM2L`
  assembly to materialize `Op` on host once, then upload; or assemble on device. Include the
  Lamb-Helmholtz `χ` channel with its `P+1` sizing via the existing `basis_info`/order
  accessors (see `OperatorBasisInfo`, `phi_slab`, `flat_basis_index`).
- Gather the batch's source columns from resident `state.multipoles` into
  `state.scratch.m2l_*` using a **device gather kernel** keyed by `route_sources`.
- Run `CUDA.CUBLAS.gemm_strided_batched!` (or a fused custom kernel) — `Op` × source batch.
- Scatter-add into resident `state.locals` keyed by `route_targets` using a device kernel with
  `CUDA.@atomic`.
- No host `FlatCoefficientBuffer`s anywhere in this path.

**B2. M2M / L2L on device.** Parent–child offsets are **not** translation-invariant, so batch
by unique offset (few classes) or issue per-edge small GEMMs over the resident buffers. Drive
the level-ordered edge lists (`m2m_parent_routes`/`m2m_child_routes`,
`l2l_parent_routes`/`l2l_child_routes`) and `node_centers`/`node_levels` from **device metadata
via kernels**, not host scalar reads. Reuse the B1 gather/GEMM/scatter primitives.

**B3. L2B / B2M.** B2M device kernels already exist (`_launch_cuda_b2m!`, ~line 1059) — leave
them. For L2B, remove the `@allowscalar` wrapper (~line 1376): the per-cell local-column pack
(`_pack_flat_column!`) and `evaluate_local` must run inside a device kernel reading
`state.locals` directly. The existing direct-pairs nearfield kernel
`_cuda_direct_pairs_output_kernel!` (~line 1201) is already device-resident — keep it.

**B4. Float32 allocation watch (022 deliverable / 016b item 5).** Ensure the device Float32
path allocates no per-call scratch inside any resident pass. Record before/after allocation
counts in the Phase C script output.

**B5. Make residency self-enforcing.** Wrap the lifecycle test/script run in
`CUDA.allowscalar(false)`. With the `@allowscalar` blocks gone, any residual host scalar access
throws — proving residency rather than asserting it. Re-add `state.scratch.*` residency
assertions to `_assert_cuda_resident_stage!` now that the kernels use them (reverses A2's
interim removal).

**Files:** `src/translate_batched_cuda.jl` (all four operator stages + gather/scatter/GEMM
helpers); `src/containers.jl` only if new scratch/GEMM-workspace fields are needed on
`DeviceResidentRadixState`.

**Phase B local check:** cannot run GPU here. Confirm the package still loads and CPU tests
stay green (the CUDA file is not included unless `load_cuda_radix_lifecycle!()` succeeds):
```sh
julia --project=. -e 'using FastMultipole; @assert FastMultipole.cuda_radix_available()==false; println(FastMultipole.cuda_radix_status())'
julia --project=. test/cuda_radix_lifecycle_test.jl
```


The script must:
- Call `FastMultipole.load_cuda_radix_lifecycle!()`, then print `CUDA.versioninfo()` / device
  name and `FastMultipole.cuda_radix_status()`; abort clearly if CUDA did not load.
- Build a randomized multi-cell system; run `run_host_radix_lifecycle!` (oracle) and
  `run_cuda_radix_lifecycle!` (device) for `Val(false)`, `Val(true)`, `Float64`, `Float32`.
- Assert **output parity** `Array(device.output) ≈ host.output` (full output, not just root
  multipoles) at appropriate rtol/atol per precision.
- Assert transfer counters: host-origin ⇒ 1 body upload + 1 influence download; device-origin
  ⇒ 0 uploads + 0 downloads; **all** runs `expansion_host_copies == 0`. Run everything inside
  `CUDA.allowscalar(false)`.
- Run the `008c` break-even throughput sweep (batch sizes incl. 8 and 64; device-resident
  dense vs. CPU recurrence) and print a timing + allocation table.
- End with a compact machine-readable `PASS/FAIL` block + key numbers for easy copy-back.
