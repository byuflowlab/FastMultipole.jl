## Objective

Implement four radix M2L traversal strategies side-by-side behind one shared
pair-visiting interface:

1. Rigid implicit stencil baseline.
2. Per-offset sparse intersections.
3. Blocked occupancy bitsets.
4. Lazy materialized batches.

The purpose is to avoid the cost and allocation pressure of the existing explicit
source-target M2L pair vectors, while also avoiding excessive empty-cell probes on
sparse uniform grids.

## Strategy Details

### 1. Rigid Implicit Stencil

Baseline implementation:

- Precompute accepted offsets once.
- For each occupied target cell:
  - decode target coordinate;
  - for each accepted offset `d`;
  - compute `source_coord = target_coord - d`;
  - call `radix_cell_index(grid, source_coord)`;
  - visit the pair only if the source cell exists.

Properties:

- No M2L pair allocation.
- Work scales like `occupied_targets * stencil_size`.
- Can waste probes badly on sparse grids.
- Important as a correctness and benchmark baseline.

### 2. Sparse Offset Intersection

CPU-oriented sparse candidate:

- For each accepted offset `d`, stream occupied cells and look for the shifted
  partner.
- Preserve per-offset traversal order, so the operator layer can still batch by
  offset.
- Avoid scanning empty target/stencil combinations as much as possible.

Implementation options:

- Start with the simple version: for each occupied target cell, compute shifted
  source coordinate and use `radix_cell_index`. This is semantically close to
  rigid implicit but grouped by offset.
- If performance warrants within the task, improve by storing or deriving decoded
  occupied coordinates and using sorted/intersection-style traversal. Morton keys
  cannot be shifted by simple integer addition for arbitrary 3D offsets, so exact
  coordinate offset plus re-encode or coordinate side storage is required.

Properties:

- Allocation-light.
- Natural per-offset batching.
- Likely best CPU sparse-grid candidate.

### 3. Blocked Occupancy Bitsets

GPU-shaped sparse occupancy index:

- Partition the uniform grid into fixed-size bricks, default `4 x 4 x 4`.
- Store occupied brick keys and local occupancy masks.
- Use bit operations to skip empty regions and enumerate only occupied local cells.
- For CPU implementation in this task, it is acceptable to construct the brick
  index on CPU and use it through the same visitor interface.

Minimum implementation:

- Build a brick index from `RadixGrid.cell_keys`.
- For each brick, store:
  - brick coordinate/key;
  - local occupancy mask;
  - mapping from occupied local cell to `RadixGrid` cell index.
- During traversal, use accepted offsets to identify possible source bricks and
  then enumerate occupied local source cells from masks.

Properties:

- More complex than sparse intersections.
- Can skip large empty regions cheaply.
- Likely best GPU direction for sparse grids, and useful input for future task
  `022` device-resident M2L.

### 4. Lazy Materialized Batches

Hybrid strategy:

- First pass counts hits per accepted offset.
- Offsets whose hit count exceeds a configurable threshold are materialized into
  `RadixM2LBatch`.
- Sparse/cold offsets remain implicit through the fallback visitor.

Default:

- Use a conservative threshold, exposed as a keyword or field.
- Preserve exact classification equivalence with the other strategies.

Properties:

- Good compromise for mixed occupancy.
- Lets dense/hot offsets feed GEMM/GPU-style execution without forcing all pairs
  to allocate.
- Requires benchmark-driven tuning.

## Direct Complement

All strategies must support the direct/near/self complement:

- Self: `d == 0`; controlled by `self_induced`.
- Near: `d != 0` and `d` is not in the accepted stencil; controlled by
  `nearfield`.
- Far: accepted offsets; controlled by `farfield`.

When all switches are enabled, every ordered occupied cell pair must be covered
exactly once by either M2L or direct/self. At body level, every ordered body pair
from `radix_body_indices` must also be covered exactly once.

If `farfield=false`, suppress M2L visits; do not silently reroute far pairs to
direct. If `nearfield=false` or `self_induced=false`, suppress only the matching
direct contribution.

- `farfield`, `nearfield`, and `self_induced` switches suppress only their own
  contribution.
