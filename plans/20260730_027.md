## Mathematical and data-layout contract

Task 025 established the following fixed facts; do not rederive or alter them:

- Near set: `N(q) = {o in Z^3 : |o|^2 <= q}`, with `q = 12` (theta=0.5) or
  `q = 3` (classic `|o|_inf <= 1`).
- Each source node has phase `u = source_coord .& 1`.
- A push offset `o` is active for phase `u` iff `o` is not near and
  `fld.(u + o, 2)` is near.
- Counts:
  - q=3: 27 near offsets, 189 push offsets per phase, 316 union offsets.
  - q=12: 179 near offsets, 1253 push offsets per phase, 1740 union offsets.
- Levels are `L = 2:ell`; classes are ordered level-major then union-offset-major:
  `global_class = (L - 2) * noffsets + k`.
- Inside a class, sources are ascending flat node index. This exact ordering is part
  of host/device parity and feeds class-contiguous resident launchers.
- For a source coordinate `c`, target coordinate is `c + o`; emitted endpoints are
  flat node indices, not leaf indices.
- Direct pairs use only the leaf-level near set.
- Dense operator scaling is
  `K(s*r0) = s^-1 Lambda(s) K(r0) Lambda(s)` with asymmetric LH degree diagonals
  already encoded by the host dense plan. Binary level scales are exact powers of 2.

## Implementation sequence

### 1. Add a CPU-load-safe device hierarchical context

Add shared type definitions in `src/containers.jl`; CUDA arrays themselves remain
constructed only in `translate_batched_cuda.jl`.

Prefer a concrete `DeviceHierarchicalM2LContext` analogous to
`HostHierarchicalM2LContext`, parameterized for its array/plan types. It should own or
reference:

- host `RigidHierarchicalTables` for construction/oracle metadata;
- persistent device `node_at::CuVector{Int32}`;
- device `level_base`;
- device push-offset matrix;
- device phase membership (`class_of`, or compact CSR if measurement justifies it);
- device/global class metadata needed by plan refresh;
- fixed `window_classes`;
- fixed route flag/prefix buffers sized for one window;
- host scalar scan staging already permitted by the current lifecycle;
- allocation-free telemetry: total routes, per-level routes, per-level occupied nodes,
  last-window route count, optional per-stage/per-level timing storage.

Keep flat and hierarchical contexts distinct enough that flat code and its storage
remain unchanged. Do not overload the meaning of flat `cell_at`, `d_accepted`, or
`class_chunk` unless doing so remains concrete and obvious.

Construction must upload `push_offsets`, phase membership/index data, class-level
metadata, and any invariant operator map exactly once. These are construction/operator
uploads (~140 KiB for q=12). Record the counter increment consistently; recurring
updates must not change `route_uploads` or `operator_uploads`.

### 2. Wire hierarchical cache construction

In `RadixFMMCache`, retain the existing `_verify_hierarchical_classifier!` gate before
device construction. This rejects a `stencil_epsilon` that does not reproduce the
requested rigid near set.

In `_radix_cache_device_build` branch on the policy:

- Flat: preserve existing allocations and behavior byte-for-byte where practical.
- Hierarchical:
  - construct `RigidHierarchicalTables`;
  - use `_hierarchical_class_metadata` for the three non-dense strategy lineages,
    because their plan tables are correctly level-true through `effective_offsets`;
  - allocate dense `node_at` of
    `sum(8^L, L=0:ell) = 1.1428 * 8^ell` Int32 entries, subject to the policy's
    byte/ell threshold;
  - decide explicitly what device fallback is supported when dense occupancy is
    disabled. The host has a Morton binary-search fallback. Implement the matching
    device lookup or reject unsupported settings with a precise construction error;
    never silently allocate beyond the configured threshold;
  - size route buffers for one level/window using the host capacity formula:
    `min(K * max_level_nodes, max_level_nodes^2)`;
  - keep direct capacity leaf-near only;
  - allocate flag/prefix storage for `K * max_level_nodes`, not all classes or all
    levels;
  - allocate plan scratch for the maximum complete window, including wide-window
    cases; task 026 found that flat chunk sizing corrupts memory for window=64.

For concatenated and factored selections, follow the host semantic choice: hierarchical
execution may share the bounded concatenated per-column engine if that is still the
intended CUDA behavior, but labels and benchmark output must state the engine actually
used. Precomputed-y and dense must retain their specialized plans. Do not repeat 026's
superseded error of benchmarking concat under a precomputed-y label.

Update the dense lifecycle footprint estimator: replace the flat `G^3 cell_at` and
full-class operator assumptions with hierarchical occupancy, window scratch, offset-only
operator bytes, scale arrays, and route metadata. Include source/target scale bytes; 026
notes that its host footprint omitted them.

### 3. Refresh per-level occupancy on device

Generalize/replace `_cuda_cell_at_scatter_kernel!`:

- `fill!(node_at, 0)` once per step;
- launch over the valid occupied-node prefix `1:n_nodes`;
- read `grid.node_levels[node]` and `grid.node_coords[:,node]`;
- compute `linear = x + (1<<L) * (y + (1<<L) * z)`;
- write flat node index to
  `node_at[level_base[L+1] + linear + 1]`;
- assert at construction that the maximum flat node index fits Int32.

This removes per-cell Morton decoding. Preserve `node_at` object identity over repeated
steps and include it in the identity regression test.

### 4. Generate hierarchical direct pairs on device

Direct pairs remain leaf-only and may use a dedicated leaf near-set kernel. It must
match `build_hierarchical_direct_pairs!`:

- target cells ascending, near offsets in table order;
- target endpoint is the leaf cell index expected by the direct stage;
- source endpoint is the leaf-relative source index expected by the direct stage;
- self/near semantics are unchanged.

Do not reuse the hierarchical push-offset phase mask for direct pairs. Verify the direct
pair list against the host oracle and exact-once combined near/far coverage.

### 5. Implement source-major per-level window flag/scan/compact

Replace the flat far-route kernels with inputs
`(level, first_offset, last_offset, level_offsets, node_at, node_coords,
push_offsets, class_of)`.

Flatten exactly as the host loop:

```text
for k in first_offset:last_offset       # offset/class major
    for source in occupied nodes at L   # ascending flat node index
```

For each candidate:

1. Load source coordinate directly from `grid.node_coords`.
2. Compute phase from coordinate parity in the same x/y/z bit convention as
   `_rigid_phase_index`.
3. Reject when `class_of[phase,k] == 0`.
4. Form target coordinate `source_coord + push_offsets[k]`.
5. Bounds-check against `0 <= coord < 2^L`.
6. Look up the flat target node in per-level `node_at` (or the explicit fallback).
7. Flag iff target is occupied.

Compact into the start of the reusable route buffers, emitting:

- `route_levels[p] = L`;
- unscaled integer `route_offsets[:,p] = push_offsets[:,k]`;
- flat node `route_sources[p] = source`;
- flat node `route_targets[p] = target`;
- `route_class[p] = (L-2)*noffsets + k` for level-true non-dense plans, or the
  documented window-local/offset class expected by hierarchical dense.

Use one scan scalar download per window, as allowed by 027. Do not append windows into a
full pair list. Route buffers are overwritten and consumed window by window.

First implement the direct flag buffer (roughly 1/8 productive due to phase mask).
Only after functional parity, profile the alternative suggested by 027: rebuild a
phase-bucketed per-level source permutation in O(n_nodes) per step and iterate only the
active phase sources. Retain it only if total route-generation/lifecycle time improves.

### 6. Make M2L application windowed on CUDA

The current update builds routes and the later lifecycle calls M2L once. Hierarchical
execution requires generation and application to be coupled:

- zero `state.locals.phi` and `.chi` once before all windows;
- loop levels 2:ell, then consecutive K-offset windows;
- flag/scan/compact one window;
- refresh only that window's class partition;
- apply the strategy with `clear_locals=false`;
- accumulate per-level route counts and timings;
- after the final window set `state.counts.n_routes` to the total telemetry count,
  not merely the last-window count.

Choose one clean ownership model and test it:

- preferred: update refreshes occupancy/direct/tree metadata, while the hierarchical
  M2L launcher generates and immediately applies windows; or
- generation/application callback from update, only if lifecycle stage ordering
  (B2M -> M2M -> M2L -> L2L -> L2B) remains explicit and testable.

Never apply M2L during update before B2M/M2M has produced the source expansions.

Update `DeviceResidentRadixState.interaction_list` from `nothing` to the concrete device
hierarchical context so `_launch_resident_m2l!` can dispatch without a boolean residency
flag. This follows `START_HERE.md`'s future-dispatch guidance.

### 7. Make plan refresh assertions window-local

Adapt the three current global refresh functions:

- factored `_cuda_refresh_factored_m2l_routes!`
- precomputed-y `_cuda_refresh_precomputed_y_m2l_routes!`
- dense `_cuda_refresh_dense_m2l_routes!`

Each refresh must histogram only the active window classes, set only corresponding
counts/starts/groups, and assert that their sum equals the window route count. Stale
counts from prior windows must be zeroed or excluded. Empty windows and partial final
windows must be valid.

Avoid downloading a full `nclasses` histogram per window. The task permits traffic no
worse than the current `nclasses` Int32 histogram plus one scan scalar per chunk, but
hierarchical `nclasses = (ell-1)*noffsets` can be 10,440; prefer a K-entry window
histogram/download. Measure before adding more complex device-only prefix handling.

### 8. Implement dense offset-only operators plus level scaling

This is the strategy-specific correctness hazard.

For hierarchical dense:

- build/upload exactly `noffsets` dense matrices at one reference level/width;
- store a class-to-offset map rather than `(ell-1)*noffsets` duplicate matrices;
- for each level/window apply task 025's source diagonal before the dense operator
  and target diagonal after it;
- mirror the host exponents currently constructed at
  `src/translate_batched.jl:4425-4444`, including asymmetric LH phi/chi rows;
- apply scales in the fused dense kernel as row factors, or in gather/scatter kernels
  for the GEMM reference drivers; keep an independently testable unfused/reference
  route;
- include scale arrays in persistent memory accounting.

The other three strategies keep level-true plan data from effective offsets and must
not receive `Lambda` scaling.

Verify seeded nonzero chi, not only gravitational chi=0. Task 026 added this specifically
because zero chi cannot expose asymmetric LH scaling errors.

### 9. Preserve lifecycle contracts and CPU-only behavior

Across two or more warmed updates with changed in-box positions:

- `route_uploads` unchanged after construction;
- `operator_uploads` unchanged after construction;
- `expansion_host_copies == 0`;
- `metadata_downloads` follows the existing contract (currently +3 per step only for
  host-resident target finalization); hierarchical work adds none;
- all persistent device arrays retain identity, including `node_at`, stencil tables,
  route/direct buffers, flags/prefixes, plan scratch, expansions, and scale storage;
- `CUDA.@allocated` for warmed hierarchical M2L and complete repeated lifecycle does
  not regress relative to the accepted device baseline, allowing only already-documented
  CUDA sort-pool behavior;
- CPU-only import remains CUDA-free;
- CUDA-absent `RadixFMMCache(...; device=true)` still throws via the existing gate.
