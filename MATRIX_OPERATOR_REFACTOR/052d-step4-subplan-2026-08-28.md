own unit/parity tests before the next. Under D1 (device-native) EVERY stage

segmented sort), B moderate (was small — device B2M kernel), C heavy (the
M2L kernel + table wiring), D small-moderate, E moderate, F small-moderate,
G moderate.

## 5. Risks

- C is the long pole: per-class table reuse across a DIFFERENT node set may
  have hidden self-pass assumptions (single occupancy, node numbering) —
  budget a shakedown pass reading the table-builder code before committing to
  the reuse claim.
- Device-native producers (D1) mean NO stage of the per-step path is
  CPU-testable locally — every correctness question waits on GPU queue time.
  Mitigation: host oracle bit-compare harnesses written alongside each stage
  so one sbatch validates everything at once.
- Segmented device sort at ell_x: no existing kernel — new code; the
  counting-sort scratch (cuda:6483-6488) does not extend past ell.
- Per-step producer cost on device is unmeasured (host prototype was
  0.015–0.05 s); measured in the Step-5 sbatch timing stage.
