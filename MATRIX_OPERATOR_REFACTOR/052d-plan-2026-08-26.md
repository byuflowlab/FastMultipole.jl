## Objective

Replace the brute-force (dense) panel-influence legs of the 052 GPU step with
FMM-accelerated evaluation, cutting the two dominant flat panel legs:

| leg (timer label) | cost (probe 13497199, mature 209k) | scaling today |
|---|---|---|
| `rotor_panels_to_particles` | 1.98 s/step | O(N_panels · np) — linear in np with a large constant |
| `panel_cross_targets` | 0.82 s/step | O(N_panels²) cross-body — N-independent |
| (`wake_to_rotor_panels`, `wake_to_probes`) | 0.13 + 0.10 s/step | small; keep dense |

Context: total_step ≈ 6.0–6.3 s at np≈242k. The particle self-influence already
runs through the radix GPU FMM at 0.097 s/step — the panel legs are now the
largest single remaining cost (052c-plan-2026-08-26.md:303-312,642-645, P2
bullet 3 "flat panel legs — unruled").

   `buffer_to_target_system!`/`influence!` for `AbstractBody`:
   `FLOWPanel.jl/src/FLOWPanel_abstractbody.jl:1124-1357`; `body_to_multipole!`
   + `has_vector_potential` for lifting bodies

   VortexRing/mixed to these (`FLOWPanel_liftingbody.jl:736-950`,
   `FLOWPanel_nonliftingbody.jl:231-241`).

   self-influence only; `FLOWVPM_fmm_radix.jl:738,775`; v1 restriction

## Design

### Phase 1 (recommended v1): host tree-FMM for panels→particles

Route the `rotor_panels_to_particles` (and optionally
`ground_panels_to_particles`) leg through the EXISTING host `fmm!` path with
panel bodies as sources and the particle field as targets:

- **Mechanism**: in `_gpu_device_pfield_target!` / `_gpu_rect_influence!`,
  when the target is the particle field and the source is an `AbstractBody`,
  call `FastMultipole.fmm!((particle_targets,), (body,))` (via
  `FastMultipoleBackend`-style plumbing) instead of `direct_rectangular!`.
  Follow the I3 split-call pattern — small fixed targets stay dense.
- **Target view**: particles are device-resident in the 052 config. Reuse the
  existing host mirror (`_wake_monitor_host_pfield` /
  `_gpu_sync_mirror_from_device!`, `FLOWPanel_gpu_wake.jl`) for positions
  (D2H ≈ 6 MB at 242k, measured `d2h_mirror_sync` 0.054 s and it may already
  have run this step); accumulate U (+J) results back with one H2D copy +
  device axpy into the U/J rows (≈ 12·np·8 B ≈ 23 MB, a few ms on H200).
  A thin probe-like target system (positions in, U+J out; the existing
  `ProbeSystem` pattern) avoids touching FLOWVPM types.
- **Derivatives**: the leg needs U and J → `DerivativesSwitch` gradient +
  hessian on the target side (supported; dense leg's 12-row output today).
- **FMM parameters**: start from the solver pin (p=4, ncrit=50, theta=0.4,
  Barba MAC; `FLOWPanel_fmm.jl:111-119`) but treat (p, theta, leaf) for this
  leg as tunable; a `tune_fmm` pass or small sweep on the near-peak probe
  decides. Cache the `FmmPlan`/tree across the step's calls where possible;
  the panel tree (source side) is rebuilt per step only if the body moved
  (it rotates every step → rebuild; N_panels is small so the tree build is
  cheap).
- **Threads**: host fmm! is multithreaded; the H200 node allocation is 64
  CPUs, and the leg overlaps nothing today (fully synchronous) — expected
  cost O(0.2–0.5 s) vs 1.98 dense, bounded by a probe measurement (gate
  below). [Local dev runs: ≤4 threads.]

### Phase 1b (same mechanism): `panel_cross_targets`

The cross-body panel→panel leg (0.82 s/step) uses the same seam — targets are
another body's control points (a fixed small-to-moderate set). Route through
host `fmm!` only if N_panels² is actually large enough to win (at `40_40` it
may not be; at `45_185_ct4` it is). Decision by probe measurement, per mesh.

### Phase 2 (only if Phase 1's ceiling is insufficient): device-side panel FMM

The previously-scoped vehicle — cross-system radix (Option A) — is rejected
(see "Where things stand" #4): the blocker is source heterogeneity, not just
`targets===sources`. If Phase 1's host round-trip proves to be the bottleneck,
the realistic device options are, in increasing effort:

- **2a. Device L2B only**: form the panel multipole/local expansions on host
  (cheap: N_panels is small) and evaluate the local expansions + nearfield at
  the device-resident particles with a new device kernel — no host mirror of
  the targets, no radix surgery.
- **2b. Panels as first-class radix sources**: panel B2M + device panel
  direct kernel + heterogeneous strength plumbing inside radix
  (`theory/panel-multisystem-scoping.md:24-26` prices this as "strictly more
  work than (A)'s already-large aliasing surgery") — the long-term goal of
  `:163-169`, not something to start from this item.

Do NOT start either until Phase 1 numbers exist.

## Key risk: science fingerprint / gate tolerances

Dense panels→particles is exact; FMM is approximate. The 052 pinned CPU
reference and locked tolerances (CT cycle-mean diff ~5e-6 abs / 7e-5 rel,
Γ rms 5.4e-5) were generated with the dense leg. Switching introduces a
controlled error into every particle's convection. Options, for Ryan to rule:

- **(a) Hold the locked tolerances** — pick (p, theta) so the leg's field
  error ≪ gate tolerances (e.g. rel err ≤ 1e-6 → p likely 8–10; costs more
  than p=4), validate with the 36-step mature gate before any long run.
- **(b) Re-pin** — accept a modest (p=4-ish, ~1e-4) error, regenerate the
  pinned reference + tolerances once (the I6 machinery exists). More
  performance, new fingerprint.
- Recommendation: (a) first — it needs no re-pin and the panel-source
  expansion converges fast (smooth far field, small panels); fall back to
  (b) only if the probe shows the high-p cost erases the win.

### Phase 2b-revised design — shared-radix dual-tree device FMM (2026-08-27)

Drafted with Ryan after the gate fail. Replaces the original Phase 2b
("heterogeneous multi-system radix redesign", deferred at lines 65–75 /
149–151) with a much cheaper graft onto the existing device radix FMM.
Also supersedes two rejected alternatives: (i) tuning the host route
(15.8 s/step measured vs 0.2–0.5 s estimated; even a 4× tune misses the
gate); (ii) a precomputed panels-to-particles influence matrix (no reuse:
the leg fires once per step and both endpoint geometries move every step,
so the per-step refresh IS a dense pass; memory is also a hard wall at
4-rotor scale, ~PB for U-only F32).

**Core idea — one implied global radix grid.** Every tree (particle
self-tree, panel source tree, control-point target tree) is a sparse
subset of a single conceptual grid: shared root box (particles ∪ panels;
in practice the particle box, since the rotor sits inside the cloud) and
shared per-level spacing. A cell is fully described by Morton index +
level; centers and half-widths are computed on the fly by index
arithmetic — no stored cell geometry. Consequences:

1. Cross-tree M2L lists are the classical same-level stencil applied
   across two sparse index sets — pure index arithmetic, reusing the
   self-interaction's stencil machinery.
2. M2L translation vectors are quantized to a finite per-level offset
   set, so rotation-trick operators (Wigner rotations per offset class)
   are cacheable on device instead of built per pair.
3. `shrink=true` boxes break alignment — the cross pass uses raw grid
   boxes (slightly looser MAC / more near-field, acceptable; the device
   radix tree is grid-based natively).

**The two cross legs, asymmetric in what they need:**

| leg | reused | new |
|---|---|---|
| particles → panels (solve RHS / wake-on-body) | particle source multipoles (already computed by the self-pass upward sweep) | small target tree over ~9k control points; cross M2L; L2B at control points |
| panels → particles (the failed-gate leg) | particle tree + its stencil machinery + device `direct_rectangular!` panel kernel for near-field | panel B2M (~9k panels — host-computed, coefficients uploaded); cross M2L into particle-tree cells; a SEPARATE small downward pass (below) |

**Downward-pass decision: separate pass, not merged locals.** Merging
panel M2L contributions into the particle tree's local expansions (one
shared L2L+L2B) is elegant but wrong under current defaults, for two
reasons flagged by Ryan:

1. *Hessian asymmetry.* The panel leg is U-only by default
   (`PANEL_WAKE_HESSIAN_TO_PARTICLES=false`); the particle self-pass
   evaluates U and J. Merged locals would push the panel contribution
   through the same L2B that computes J, silently injecting panel-J onto
   particles.
2. *Expansion-order mismatch.* Panel-on-particle currently runs a higher
   $p$ than particle-on-particle. Zero-padding particle locals to the
   larger $p$ is mathematically fine but makes the shared L2B run at the
   higher order for everything — taxing the large self-pass to serve the
   small cross-pass.

A separate downward pass over the same tree costs one extra L2L
(negligible: $O(n_{cells} \cdot p^3)$ with rotations, interior cells
only) plus one U-only L2B ($O(n_p \cdot p^2)$, embarrassingly parallel —
est. few–tens of ms on device at 242k targets, $p=4$–$8$). Merged locals
stays as a later optimization only if the J default or the $p$ split
changes.

**Expected cost.** Marginal per-step work = panel B2M (host, ~9k panels)
+ small cross M2L batch + separate downward pass + neighbor-list
near-field via the existing device panel kernel (a small fraction of
today's all-pairs 3.3 s). Plausibly well under the 0.6 s/step gate;
memory is trivial (coefficients, not matrices). Particle churn (np
changes per step) is a non-issue — the tree is rebuilt per step anyway.

**Open items:** (a) lifecycle hook in `UJ_fmm_gpu!` to run the cross

choice per leg (independent, given separate passes); (c) panel-tree
depth vs particle leaf level (cap at particle leaf level, or allow

channel handling for source+vortex-ring panels (same Laplace family —
expected compatible, verify).

**Sequencing:** (1) host profile of the failed leg (calibrates what the

## Kernel derivation — line-convolved Gaussian ("LineGauss"), 2026-08-28

Task (Ryan, 2026-08-28, handoff `052d-handoff-prompt-2026-08-28c.md`):

a TRUE integration of the particle erf/Gaussian core over the segment.

**Result: the blob-line convolution has an exact CLOSED FORM.** With the
FLOWVPM Gaussian blob velocity function g(t) = erf(t/√2) − √(2/π) t e^(−t²/2)
(odd extension), segment coords z1, z2 = z1 − L (axial), h (line distance),
R1, R2 (endpoint distances):

u = Γ/(4π h) · b̂ · [ z1 g(R1/σ)/R1 − z2 g(R2/σ)/R2
                     − e^(−h²/2σ²) (g(z1/σ) − g(z2/σ)) ]

(the 3-D Gaussian separates along the line, so integration by parts against
the singular antiderivative leaves an elementary remainder — proof in
DERIVATION.md §2). Equivalent D-form: u = c q W/(4πA), i.e. the shipped
singular kernel times a scalar W(h, z1, z2). The cancellation-reduced
implementation costs 4 erf + 1 exp per edge
(vs 1 expm1 shipped); near-field only.

Key structure:
- L→∞ limit is EXACTLY the shipped Gaussian 1 − e^(−h²/2σ²): the shipped
  kernel is the infinite-line limit of the true convolution.
- σ→0 (or far field) limit is exactly the singular kernel; deviation decays
  as poly·e^(−d²/2σ²) with d = distance to the SEGMENT — the along-line
  channel closes by construction.
- ∇u is closed-form too (cylindrical assembly, DERIVATION.md §5), but ∇D is
  no longer κ∇A: the enum contract needs two scalars (∂W/∂h, ∂W/∂z) — the
  one integration-shaped consequence.

### Bug found and fixed: axis-guard threshold scaled with ẑ²

The new closed-form test (h = 0.2rc on a 400 m filament, ẑ = ±4000)
FAILED: got exactly $|c| M_{axis}/(4\pi\sigma^2 L) = (1/\pi)(1 - 6.25\times 10^{-8})$
= 0.3183098662894228 vs expected 0.3151479 — the ĥ→0 axis limit, missing
its $O(\hat h^2)$ correction (1% at ĥ = 0.2). Root cause: `_lg_axis_guard`
used `ĥ2 < 1e-8·min(ẑ1², ẑ2²)`, so for long segments the guard fired at
physically large ĥ (ẑ = 4000 ⇒ ĥ² < 0.16). The general branch's
cancellation error is ~eps/ĥ² INDEPENDENT of ẑ, so the ẑ² scaling was
unjustified; the crossover with the axis-limit truncation error
(≈ 0.25·ĥ² rel) sits at ĥ² ≈ 6e-8. Fix (port + prototype kept in sync,
k01 T6/T6b/T6c seam probes moved to the new seam): fixed threshold

$$\hat h^2 < 10^{-7} \quad (\text{both-side error} \le \sim 2.5\times10^{-8}).$$

Production impact: NONE on 052d data. The old guard misfired only for
min ẑ² > 10 with ĥ² < 1e-8·min ẑ² — for σ = 1 mm rotor panels a
micron-thin sliver along the extended edge axis where the axis limit was
accurate to ≤ ~1e-6 anyway; the 1% error needed ẑ ~ 4e3 (meters-long
filaments). p32g/k02/k03 numbers stand.
